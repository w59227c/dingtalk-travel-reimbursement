# 产品与业务契约

本文保存当前产品范围、业务规则和输入／输出契约；状态转换与集成细节见 [OA 集成设计](DINGTALK_OA_INTEGRATION_DESIGN.md)。修改业务行为时同步维护相关章节，根 README 只保留使用入口。

## 当前交付范围

- Vue 3 + TypeScript H5、FastAPI 单体后端、SQLite 配置库。
- 钉钉免登。报销人姓名由后端根据登录人的钉钉身份或已核实的代报对象确定，部门是服务器核验后保存的办理信息。
- 公司、预算代码从已确认的钉钉表单选项读取；预算代码完整标签直接填 Excel 项目。
- 出差补助为可选项；不连续审批分别生成补助项，重叠审批合并后只计算一次。每日标准按审批中的完整出差类别读取，八类分别配置，支持 0 元；不按天数重新判断长短期。每项补助在原审批日期下提供可编辑的补助日期，只允许位于该审批（重叠审批合并后）的日期范围内。收窄日期沿用延后出发/提前结束调整，可另外添加中途非补助时段；各段不能重叠或重复，并保存到草稿及提交快照。计算说明全页只显示一处、默认折叠；桌面和移动端共用“补助开始／补助结束”分组，中途非补助时段也按“离开／返回”分组；每组同时编辑日期和时段，桌面左右排列、移动端上下排列，双端功能一致。
- 票据支持 JPG、JPEG、PNG 和独立单页 PDF；行程单等证明材料还支持最多 30 页 PDF。
- PDF 文本优先，必要时使用 PP-OCRv6 small 模型与 ONNX Runtime CPU 做本地识别；同时尽力本地解码旧版发票二维码作为金额和开票日期的交叉校验证据，不调用付费 OCR 或大模型 API。
- 自动解析铁路电子客票、旅客运输电子发票、纸质出租车小票，并尽力提取国外票据的原币总额和日期；通用票据保守兜底。
- 市内交通类型以 OCR 结果作为默认值，员工可在编辑费用时改正；最终选择为网约车时显示行程单关联入口，出租车不提供行程单选择、上传、自动匹配或推荐，已有关系保留，网约车缺少行程单会阻止提交，同一份多行程文件可被多笔费用分别选用。材料持久区分行程单、付款凭证和普通附件。OCR 未识别出具体说明时使用费用类别名称作为说明，不要求员工重复填写。
- 桌面和移动端的行程单、住宿明细、付款凭证及运单明细均通过该栏右侧唯一的“关联…”入口打开专用弹窗，核对本笔费用摘要、选择已有材料或上传新文件，再“确认关联”。上传不会直接改变费用关联；取消保留原有关联，成功上传的文件留在材料列表。确认只更新该笔费用的对应材料关系，移除选择不删除文件或改变其他费用的共享引用；“编辑”仍打开完整费用表单。行程单可在弹窗内切换单选和多选，已选多份时切回单选需指定保留哪一份。
- 单张票据的员工确认人民币金额严格超过 500 元时需要关联付款凭证；500 元整不要求。无来源发票的手工汇总行在 `receiptCount > 1` 时，不按合计金额强制要求付款凭证；关联来源发票仍固定按 1 张判断。目前铁路豁免仅限明确的 `high_speed`，未把全部火车票作为豁免。员工可把识别为高铁的票种改成动车或普通列车并采用更严格的付款凭证规则，但不能把已识别的动车或普通列车改成高铁取得豁免；最终铁路范围待业务确认。
- 无“支付成功”提示的银行卡交易明细，在同时具备卡号、消费描述、正结算金额、交易日期和不早于交易日的记账日期时，也可自动识别为付款凭证；退款、失败、待入账等不确定记录仍需确认。明确人民币结算金额、交易日期和摘要可作为手工录入参考，不自动产生费用或推断费用类别。
- 国外票据的原票币种、原币金额为选填参考；人民币报销金额由员工另行填写确认，即使原币信息留空也须确认人民币金额。员工修正或清空原币币种、金额后，以该人工结果为准，后续保存和恢复不会再用旧识别值覆盖。
- OCR 结果可编辑、删除，也可完全手工新增费用明细。手工费用支持上传或选择多份票据照片/文件，多张小票可合拍；不自动识别，合计金额和票据张数由员工填写，关联随草稿恢复并进入提交汇总。重新识别只更新文件证据；费用行已经有人工修改时保留现有明细，不用新结果自动覆盖。
- 桌面费用明细的「类型」列和手机费用卡片提供单选下拉，可直接选择或更正费用类别；普通费用使用当前 OA 费用科目，差旅使用可手选的费用类别。日期或金额尚未补全时也能先改类别，保留该行其余输入及来源票据，沿用自动保存和刷新恢复。新类别的交通类型、铁路票种、福利细分及适用材料关系按既有规则核对，解除不适用的行程单或运单关系时不删除文件；完整编辑仍可核对细分和其他字段。只读、材料操作中、完整编辑或材料关联弹窗打开、选项加载及加载失败时不能快捷改类。
- 管理员可在每日补助设置之前按费用类别维护关键词；所有关键词规则一致，均可直接新增、修改、移动类别或删除。
- 关键词保存期间暂时锁定编辑、取消关闭和其他关键词操作；失败保留输入供重试。禁用前排队的较新输入不会被旧保存结果清除，继续保存时更新同一条关键词。
- 明确标签或 PDF/图片版面列中可靠识别的销售方名称也参与关键词匹配，匹配不依赖其所在交通分组；网约车、出租车和通用只控制交通类型及行程单要求。销售方角色不明确时，不凭公司名称的排列顺序猜测。
- 页面默认标题为“智能差旅费报销申请”。系统管理员可在设置中修改标题，并从钉钉通讯录选择额外管理员员工或部门。指定部门的直接成员拥有系统管理员权限。配置文件中的初始管理员始终保留。
- 桌面和移动报销页默认办理本人报销。有权限的员工可以选择同企业的同事代报，页面显示当前报销人，并提供返回本人报销的入口。系统设置可从组织架构选择允许代报的部门，或按姓名与准确的钉钉 userId 查找员工。已有授权优先展示通讯录名称，名称无法回查时展示已保存的 ID。匹配员工或直接部门中的任一项即可代报，授权按企业保存，管理员更新授权使用版本校验。
- 代报选人、额外管理员员工和代报授权员工的姓名搜索按钉钉 `userId` 区分同名员工。结果显示姓名、从通讯录查询到的当前部门名称及 `userId`，多部门用顿号分隔。部门名称暂时无法取得时仍可通过 `userId` 核对员工。设置页的已授权员工标签也显示 `userId`，便于核对和撤销同名员工的授权。
- 代报复用现有选择审批框，只列出报销人发起、已通过并确实抄送给当前登录人的出差审批。后端读取已执行的 `PROCESS_CC` 抄送记录，按实际经办人的 userId 精确匹配。保存关联、预览可编辑草稿及新提交时重新核验。抄送信息缺失或异常的审批不得关联。
- 新代报由实际登录的经办人发起钉钉 OA，可在经办人的 OA「我发起的」中查看。表单的报销人、报销部门、所属公司、预算、出差审批、费用和生成附件均按被代报员工的冻结报销内容填写。启用代报提交前，管理员须在钉钉报销模板提供「报销人」「报销部门」两个单行文本控件，并在系统设置的 OA 模板目录中完成映射。缺少映射时提示处理且保留原草稿，已有本人流程可继续使用原模板映射。仅新增代报身份映射且原报销及出差模板契约保持兼容时，原草稿可继续保存和提交，审批关联与票据留在原单。
- OA 模板目录在读取或保存期间暂停编辑；保存回包保留已经发生的后续输入并要求重新检查。其他管理员更新造成版本冲突时保留本页修改，不自动加载覆盖；明确确认重新加载后才采用服务器最新目录，加载失败仍保留输入。
- 系统设置提供仅管理员可用的“出差审批诊断”：输入员工 userId 和审批编号或实例 ID，可按默认或自定义查询日期、关键词复现正式候选查询，逐步查看上游是否返回、发起人/状态/日期是否通过，以及是否因公司、预算或类别选项而不可选择。诊断使用当前钉钉模板但不写入模板快照，不修改审批或草稿；超时、限流及回查超限明确显示为未完成，未定位到目标不等同于审批不存在。桌面、移动设置页提供相同功能，并可复制不含员工标识、审批标识和原始表单的诊断摘要。
- 系统设置提供仅管理员可用的“票据识别诊断”：单次上传一张 JPG、PNG 或单页 PDF，复用正式材料识别流程和当前分类关键词，临时查看识别原文、用途判断、解析器得分、实际命中关键词、分类输入文字及最终类别。诊断结果不写入草稿或日志，临时文件在处理结束后清理；PDF 原生文字、图片 OCR 和版面推导字段分别展示，未用于解析的提取内容会标记。诊断只需选择文件，不提供手动年份输入，使用识别流程的默认日期解析规则；取消、切换文件、身份变化或离开页面会清除旧结果。出差审批诊断保留，运行记录功能及独立采集存储已移除。
- 基于脱敏公司模板生成 Excel，预览前自动保存最新输入；正式提交有材料时合并生成票据汇总 PDF，纯补助且无材料时只生成 Excel；生成文件暂存到受控持久卷，上传并从 OA 回读确认后清理本地副本。
- 历史报销保留锁定时的 Excel 模板指纹；仅内置模板已核验的作者属性脱敏版本按固定指纹对兼容，保留旧单导出能力，不改写快照。其他模板变化继续阻断生成。
- 未完成输入自动保存并恢复；进入设置前等待当前修改保存，保存失败时留在报销页并显示原因。结构化 OCR 候选、原始附件元数据和提交状态持久保存；票据字节保存在受控 staging 卷，预览通过鉴权接口读取。
- 桌面与移动报销页顶部提供提交状态、返回报销、表单恢复和保存失败操作，管理员可在页头右侧进入“系统设置”。提交成功后当前页面显示锁定快照的金额、审批信息和只读明细。成功明细统一保留材料文件名及关联关系，不提供服务器原件预览；票据材料在钉钉审批中查看，Excel 仍可按锁定快照重新生成。报销页右上角按“系统设置（仅管理员）、报销记录、新开一笔”固定顺序显示；空白报销的新开按钮置灰，操作忙碌时保留按钮位置，移动端与应用标识同一行紧凑排列。可从“新开一笔”开始下一笔报销，有审批链接时桌面端可点“打开钉钉 OA”。查看历史明细时在顶部右侧提供“返回当前报销”，与应用标识同一行，管理员设置入口仍保留；关联审批逐张展示标题、出差日期、冻结的出差类别、审批编号及所属公司与预算项目，长名称自然换行，不新建或替换当前报销。多部门用户在选择办理部门前即可使用页头的“报销记录”和“新开一笔”。前者直接打开本人历史。已有办理部门和当前草稿时，点击“新开一笔”立即确认是否放弃旧稿，确认后打开空白报销表单。尚无办理部门且没有当前单时，从首次填写入口确认本次办理信息；已有当前单时跨部门恢复原单。取消新开时保留当前单。版本冲突后需明确核对服务器已保存内容，未保存的本页修改在用户确认前保留。刷新报销选项不替换当前草稿，移动端也无需切到最后一步处理这些状态。
- OA 表单需要管理员确认时，报销页提供直接进入系统设置的操作。模板未配置而尚未建立当前草稿的空白页，以及恢复旧草稿产生的默认值整理，都不提示舍弃修改；确实有未保存输入时，管理员须明确确认舍弃后再前往设置。普通员工看到联系管理员及重新检查入口。
- 查询并复核当前报销人已通过且符合办理权限的出差审批，将选中实例写入 OA 的 `RelateField`。选择后，所属公司、预算代码、出差类别和日期会从同一候选立即展示；服务器核验期间保持固定布局并禁用重复选择，不额外插入瞬时状态标签，失败时显示真实错误。关联保存不等待普通输入的防抖时间，最终值仍以后端复核结果为准。同一报销中的审批须公司、预算和来源出差类别一致，发起部门不同不限制关联，日期允许不连续；每张审批保留独立关联记录，重叠日期在补助计算和 Excel 明细中自动合并。新填或更正报销部门时从员工当前有效部门确定：单部门直接使用该部门；多部门时审批发起部门一致且可匹配则自动带入，否则由员工选择。当前部门候选排除名称以“其他”开头的部门，并按名称去重。审批详情读取在同一后端进程内跨用户统一限速；钉钉以 HTTP 429 或 `QpsLimitForAppkeyAndApi` 返回限流时，安全读取会有限退避重试，耗尽后明确提示接口繁忙，不再误报应用权限不足。
- 后台持久任务完成附件直传、幂等创建 OA、严格回读和确定孤儿附件的补偿清理。

报销页每种报销类型只处理一笔当前报销，填写、处理中、失败和待核对都在原页恢复，不自动开新草稿，不提供待处理列表。用户确认“新开一笔”后，旧内容退出报销页；原任务和审计证据仍按原生命周期保留，后台继续核对不确定的 OA 结果。旧页面不能再编辑或提交已放弃内容。明确未创建 OA 的失败可点击“保留内容重新处理”，复制已保存内容与完整原件，原失败快照保持不变；重复操作复用同一恢复结果。复制中断可继续恢复，未完整恢复不得编辑、预览或提交；原件已不可用时明确报错，可新开补传。成功历史显示由当前钉钉用户在各部门发起的最近 10 笔 `SUBMITTED` 记录，含本人报销和代办报销。恢复后的报销再次明确失败时，以这次失败的报销为来源恢复最新已保存内容；只有材料尚未恢复完成时，才向上一恢复来源续传。恢复前若本页存在真实未保存修改，须明确确认按已保存内容恢复，取消则保留本页且不发起恢复请求。

差旅和普通费用每种各保留一张当前草稿，按企业、报销人和经办人隔离。部门只是已保存的办理属性，不参与访问授权、列表过滤或前端状态隔离；已有单的更换部门入口直接使用原单部门，不要求 Session 预先选择部门；部门变化不清除输入、本地上传失败文件或重试入口，也不使原单只读。恢复、建单和失败恢复均跨部门查找当前单，切换报销类型分别恢复各自的原单与材料。切换报销人时，一致回读的同一目标单即使部门已被其他页面更正，仍采用最新已保存部门；已退出工作区或办理身份不匹配仍拒绝采用。失败恢复保留来源单的部门属性，之后可更正；核对页、代报提交确认框和新提交均使用报销单已保存的部门，不使用其他页面的 Session 部门。已提交记录、在途 OA、恢复任务和审计证据继续按原生命周期处理。

准备当前草稿时，服务器先在同一事务内查找已有记录，复用时保留原单部门，不因页面旧部门已失效而拒绝恢复。确实新建或经用户确认替换时，核验并采用本页明确选择的当前有效部门，其他标签页改变 Session 部门不会改写本次选择；无效选择不创建新单或退出旧单。

普通费用的基本信息保留「更换部门」；差旅仅在已选审批无法唯一确定当前有效部门且有多个可用部门时显示此按钮，未选审批、审批可自动匹配及单部门时不显示。确认前保存本页输入，取消时保留原单，确认后保留单号、费用明细、材料、文件引用及页面步骤。差旅每次新增、移除或重新确认审批时，后端在保存关联的同一 CAS 事务内重新确定可自动匹配的当前部门；无法唯一确定时保留现有属性并提供手选入口，清空审批保留现有部门。手选部门时从服务器复核全部已选审批并保留完整关联组，公司、预算、来源类别和日期按复核结果更新。原办理部门撤销或改名不使报销只读，不限制保存、材料操作、预览、任务查询和失败恢复；审批能匹配当前部门时提供「按出差审批重新确认部门」，不能匹配的多部门员工才手选。过期、锁定及恢复中的原单仍遵循原有状态保护。

过期原稿的办理部门已撤销或改名时，可以明确确认“新开一笔”；服务端按企业、报销人、经办人及原单 revision 核验后，将旧稿退出工作区并在当前有效部门准备空表，不要求先修改过期原单。原记录与在途任务、提交快照和审计证据沿用原生命周期。

办理部门已撤销或同一部门 ID 的名称发生变化时，可以先读取原单内容和材料清单；普通保存、材料处理和计算不因部门变化受限；如需更新部门，通过原单版本校验更正。普通费用允许确认同 ID 的当前部门新名称。差旅旧稿尚未关联审批时，保留选择首张出差审批的恢复入口，由服务端核验审批并确定部门，成功后继续原单；此入口不解除锁定、过期、材料恢复、版本冲突及其他只读保护。

若升级前已有多笔跨部门旧稿，先展示各笔的部门、状态、修改时间、费用与材料数量和明细摘要，要求员工明确选择保留哪笔。取消选择不修改内容；确认时在同一事务内校验全部候选的 ID 和 revision，再让其余旧单退出工作区。普通未提交材料按既有安全清理规则回收，已提交记录、在途 OA 任务和审计证据保留。选择前不自动采用其中一笔、不合并费用、不新建第二张草稿；候选有并发变化时要求重新加载核对。旧选择响应丢失后可以幂等打开已保留的原单。

部门更正使用原单 revision；响应丢失时按原单内容、目标部门、版本及办理身份确认结果，会话所选部门不同不阻断正确回读。版本冲突或真正的并发内容差异保留本页供核对，不重放到另一张单。成功但响应丢失时，只读回查同一原单与实际会话，核对部门、审批、规范业务内容、版本及状态后才接受结果；无法确认时提供重新核对，不自动另建。切换报销类型会结束原类型尚未确认的「新开一笔」。已成功的报销回执不显示新提交服务的待核对提示。

旧页面收到服务器确认的已替换、材料恢复中、过期或锁定状态后，立即停止编辑和本批文件处理，不依赖额外回读成功。已替换页面提供“打开当前报销”；确有本页未保存修改时，须确认舍弃后再切换，不覆盖或重放到当前报销。旧输入恢复时的默认值、时段格式整理不算员工编辑，不阻挡只读页面进入设置或查看成功记录，也不触发无意义的保存请求；真实修改仍受离页保护。

新开请求失败或响应丢失时，先回查服务器当前报销：已替换就打开实际当前单，未替换则保留本页输入；回查也失败时暂停编辑和再次新开，并提供“核对当前报销”入口，只读回查，不重复创建。账号、经办人或登录会话变化后，旧恢复请求的结果和错误不再影响新会话。身份读取和审批归属部门核验同样丢弃旧会话响应；变更报销部门期间暂时停止编辑，原单更正响应丢失时回读同一草稿及 Session 核对结果，不要求会话部门相同；首次选部门尚未建单时先读取真实 Session，无法核实则提示重新登录。均不重复变更，已保存内容保留。

新开成功后，普通未提交、未锁定且无恢复任务的旧报销文件后台尽快清理，不再等待原草稿到期；先保留旧草稿和文件状态信息，旧页面仍提示已替换。在途上传、识别或恢复复制尚未结束时暂缓清理，安全后重试。清理失败不影响新报销，定期扫描每 30 秒尝试，服务重启也会续扫；OA worker 关闭时仍可清理。已进入提交流程或仍需人工核对、恢复的材料继续按原任务生命周期保留，不能因新开而删除。

若原单已被过期清理且服务器确认当前记录为空，沿用用户已确认的新开操作，幂等准备空表；其他页面已准备好当前单时直接复用。读取失败不会当作记录为空，准备空表的响应丢失后也可继续核对，不会携带已失效的原单 ID 反复替换。

检测到材料恢复中的报销已过期后，停止恢复轮询，隐藏无法继续的恢复入口，统一提示新开并重新上传材料；不会自动新开草稿。

恢复记录已经不可用时保留本页只读内容供核对，停止恢复轮询并提示从右上角新开；网络超时不会被当作记录不存在。恢复复制按请求代次使用独立分片，避免多页面接管互相干扰；未完成目标文件损坏时可从完整原件安全重建，原失败快照保持不变。

材料仍在恢复写入时，过期清理保留其记录和额度，待写入结束或进程退出后安全清理，避免留下无归属文件。确认恢复已经完成后自动移除该次恢复的旧错误提示，保留后来其他操作的错误。

核对时同时检查单号、版本和状态。同一单号已锁定、过期或仍在恢复材料时不能恢复编辑；本页有未保存修改且服务器状态或内容已变化时，先保留本页输入并提示核对最新内容，由用户确认后读取。服务器仅更新版本、已保存业务内容一致时，沿用最新版本继续保存本页输入。

普通步骤切换不主动滚动页面。主动提交校验失败会定位到对应信息或材料，主动操作的全局错误会定位到错误卡片。自动保存或后台提交出错时，若详情不在可视范围，会持续显示“查看并处理”提示；手机提示位于底部操作栏上方，编辑弹窗打开时不覆盖弹窗，也不自动抢走当前输入位置。错误解决、换单或退出当前会话后提示同步清除。

核对提交前展示本次所属公司、报销部门、预算项目及逐段出差日期，可返回关联审批核对。提交确认固定当时的部门 ID 和名称；保存后与服务端复核后均核对该部门，即使费用保存成功但响应丢失、回读采用了新版本，也不能替员工同意另一页更正后的部门。部门已变时保留已保存内容、材料和步骤，提示重新核对；重新确认后继续原单提交。成功记录突出冻结金额和预算项目，操作称为“查看明细”；字段来自经过校验的提交快照，不按当前选项或补助标准重算。

移动端默认直接展示近期审批，日期和标题查询收在“筛选审批”；收起不会清除条件，有日期范围错误时自动展开。普通附加材料以中性样式展示，必须处理的材料才使用警告色；各类证明材料每栏只提供一个“关联…”入口，添加、更换和解除关联统一在弹窗内确认；文件预览和修改用途直接展示。

费用核对提示按当前费用和原始 OCR 证据重新计算，分别放在日期、金额、说明、类别或关联材料旁。员工确认完整且无矛盾的行程、修正对应字段后，已解决的提醒自动消失；低置信度、金额或编号冲突、无法确定原因的原始识别疑点仍保留，编辑保存不会统一清空。日期和说明按实际编辑动作记录，不因重新识别产生差异就当作已经核对；旧数据没有编辑记录时保留疑点。关联多份文件逐份检查编号，一份匹配不能掩盖另一份矛盾。自动关联不等于人工确认；多行程文件可供多笔费用共用，不把整份合计当作其中一笔的金额。原票币种、原币金额为选填参考，人民币金额确认按持久证据和当前输入判断，刷新前后保持一致。提示展示不改变后端完整性校验、金额或提交规则。

桌面和手机的报销提示条统一圆角，并与相邻指标、表单和操作留出独立间距。费用科目未选择或费用字段缺失时，首次恢复与编辑后的完整汇总区都显示提示条；同一错误已在提示条展示时，预览按钮下不再重复显示，不同原因分别保留。仅显示预览入口或只读时，不因汇总提示条隐藏而丢失禁用原因。预览按钮始终沿用完整校验并关联当前可见的原因说明；相同错误去重后仍保留原有重新计算入口，不显示可正常预览的帮助文案。

## 补助计算契约

审批列表按审批发起日期查询，默认最近 180 天，单次最多 180 天，并拆分为每段不超过 120 天的钉钉请求。按当前常规接口范围，仅支持上海时区最近 365 个自然日（包含今天），不接受未来日期。员工查询和管理员诊断使用相同日期限制；前端限制日期选择，后端在调用钉钉前再次校验，过期查询凭据需重新选择审批，历史锁定快照仍可回读。钉钉返回 invalidEndTime 等时间参数错误时明确要求调整日期，不再提示为服务暂时不可用。

只有出差补助也可预览 Excel 和正式提交，无需费用明细或上传材料；后端必须算出大于 0 的补助合计且补助输入完整。空费用且补助为 0 的报销不能复核或提交。有费用时仍须补齐每一行及现有证明材料；已上传的材料不得静默遗漏，仍须完成用途确认并汇总为 PDF。所有 Excel 预览入口同样拒绝尚未识别、用途待确认或未归入费用/明确忽略的来源材料，处理后可继续预览。纯补助 Excel 只写补助行和合计，票据张数为 0。

核对页按已填写的费用、有效补助和已上传材料显示预计 OA 附件。没有有效报销内容、费用缺少材料或上传尚未完成时，先显示相应提示。提交后按锁定快照显示附件清单。

市内项目出差按具体出勤日期计算，当前每日标准默认 50 元，每个选中日期计整天，不区分上午和下午。首次关联新审批时按管理员维护的年度日历排除休息日、选中调休补班；缺失完整年度日历时暂停默认选择并提示联系管理员。周末或节假日加班可补选，未出勤日期可取消。重叠审批的同一天只计算一次。扩大补助范围不自动增加出勤选择；缩小范围保留并标记越界的已选日期，仍可逐项取消，未修正前不能预览或提交。日期选择自动保存，Excel 和 OA 使用后端核验的同一份日期、天数和金额。新生成的 Excel 出勤说明按年月分行，将实际选中的连续自然日合并为日期区间（如“2026年9月：1-5日、7日”）；未出勤日形成区间断点，跨月跨年分别显示。单项补助范围和日期选择最多 3660 个自然日。旧可编辑草稿不自动套用新日期选择，需核对出勤日期，并逐项核对、删除旧的非补助时段；历史锁定快照继续使用原金额和说明。

系统设置的“节假日与调休”展示自动获取状态，并提供“粘贴内容录入”和“手动填写”。后台默认启用年度获取：按上海时区每年 11 月 1 日起每 5 天优先通过 GitHub 官方 Contents API 读取 holiday-cn 固定年度 JSON，原始文件地址作为备用，查询下一年；首次启动补查当年缺失日历。校验格式、目标年份和完整性后自动保存，成功即完成该年任务。未成功目标跨年继续重试；提前手动查询失败不会让下一年度自动轮询早于 11 月 1 日启动。任务与租约持久化，多进程与服务器重启不会丢失目标或重复覆盖已维护年份。一次获取按 API、raw、API 顺序最多尝试 3 次，短暂退避，合计不超过 20 秒；API 限流后本轮不再重打 API，年度文件 404 不重试，非法内容不因换源绕过校验。响应最多 64 KB，不跟随重定向，不接受用户 URL 或环境代理，日志只记录固定来源、状态、安全错误码和超时／连接异常类型。`ATTENDANCE_CALENDAR_SYNC_ENABLED=false` 可暂停后台轮询。管理员可指定缺失年份“立即获取”，已维护年份保留；删除年度安排会同时暂停该年自动获取，可通过立即获取或手动补录恢复。

粘贴入口支持政府年度通知、提莫年度 JSON 和 holiday-cn 年度 JSON，自动识别格式和年份。政府网查询其他年份需修改搜索词中的年份，提莫和 holiday-cn 需替换网址中的年份。粘贴解析本身离线，不访问输入网址；解析失败可修改原文或手动修正识别结果。纯手动填写无需原文，预填七类节日空日期行，填写全年放假与补班范围后生成预览。手动录入和修正都必须核对差异、显式保存，后端检查全年七类节日覆盖、有效日期、重复冲突、相邻年范围和每段最多 32 天；标题分别标记“手动录入”或“手动核对”，不持久化原文。政府通知支持省略重复月份、跨月、明确年份的跨年范围、同句放假与补休、合并节日和星期／农历括注；建议性休息不自动计入，临时延长或补充通知不能作为年度替换。

提莫 JSON 要求 code 为整数 0、非空 holiday 字典，MM-DD 键与条目完整 date 一致且都属于同一年，holiday 为严格布尔值；holiday-cn 要求整数 year、非空 days 列表及严格布尔 isOffDay，日期可涉及相邻年。两种格式都要求有效且唯一的公历日期、有效节日名称、七类节日放假覆盖；不接受报错、空结果、单日／月度缺项、混合格式、重复字段或用数字／字符串冒充布尔值。JSON 只使用日期、名称和放假／补班标志，工资倍数等元数据不影响补助。核对页显示识别格式、逐节日安排和对应原文／JSON 相关字段、保存后的只读日历及新增／修改／移除差异。第三方数据保留来源提示并要求核对完整性；修改粘贴内容必须重新解析，未明确保存前不生效。

通知明确列出的日期用于覆盖默认工作周，其余日期按周一至周五。跨年安排按通知来源分别保存，只补充相邻年份涉及的日期，不将该年视为完整维护；重新导入或删除通知时，仅替换或移除该通知的贡献，保留其他年度通知的安排，重叠时适用年份较新的通知优先。跨年日期与本年度在一次事务中保存，所有相关年份按预览版本执行 CAS；并发冲突保留原文并要求重新解析，重复保存相同内容不生成新版本。已有年度安排提供查看、修改和删除。修改时带入该年度来源及其跨年日期，年份固定，其他年度通知贡献保留；生成预览核对差异后才保存。打开编辑时记录相邻年度版本，遇到并发变更保留填写内容，通过“重新核对最新差异”读取最新版本并再次预览；相同内容不生成新版本。仅跨年补充的行须到对应来源年度修改。旧版日历继续读取，也可通过修改或完整年度通知更新。取消或离开未保存录入时需确认。桌面核对页采用左右布局，移动端全屏纵向排列；原文入口固定在节日标题行，内容展开在日期下方。核对页保留一份节日汇总，点击日期定位日历年月；日历提供十二个月快捷按钮及上／下月切换，单独查看已保存日历时的年度日期清单也可定位月份。两个模式使用相同校验和导航能力，设置卡片圆角与间距统一。

年度通知回归覆盖 2017—2026 年，两种 JSON 格式各覆盖 2023—2026 年；逐项检查日期、类型、名称、复制格式、保存结果和全年的默认出勤结果。来源与统计口径见[政府通知样本](../backend/tests/fixtures/holiday_notices/README.md)和[JSON 样本](../backend/tests/fixtures/holiday_json/README.md)。

日历及自动获取状态保存在 SQLite 的 settings 中，随数据库备份，无新增表或迁移；不内置年度安排，不持久化通知或远端 JSON 原文。日历只生成首次默认值，不改写已保存出勤选择或锁定快照。市内补助范围涉及的每一年都必须完整维护；缺失时保留草稿和材料，提示联系管理员并提供重新检查，暂停出勤选择、有效计算、Excel 预览和新提交。仅跨年补充不能算完整年度。补齐后已有选择保留，尚未填写时可显式带入默认工作日；历史锁定报销和已有提交的恢复仍使用冻结快照。自动获取成功后停止该年轮询，后续调整由管理员通过粘贴或手动填写核对更新。

以下上午／下午和非补助时段规则适用于市内项目出差以外的类别。

不申请出差补助时，无需填写补助行程信息，Excel 中不生成补助行；OA 仍关联当前报销人已通过且符合办理权限的出差审批。申请补助时，员工只需选择出发、返回日期及上午/下午；系统内部按公司时区 12:00 的半天边界换算，不要求输入具体时分。

跨日行程：

- 出发日 12:00 前出发计 1 天，12:00 及以后计 0.5 天。
- 返回日 12:00 前返回计 0.5 天，12:00 及以后计 1 天。
- 中间完整自然日每天计 1 天。

同日往返：

- 跨过 12:00 计 1 天。
- 均在同一半天内计 0.5 天。
- 结束时间早于开始时间必须拒绝。

每个补助项支持多个非补助时段，每个原始审批项最多 100 段。界面通过补助日期及出发/返回时段表达延后出发、提前结束，通过“非补助时段”添加中途离开。中途离开和返回的日期选择器只允许选择当前补助日期范围内的日期，随补助日期编辑或恢复同步更新；空的离开日期日历从补助开始月份打开，空的返回日期日历优先打开离开月份。返回日期不得早于离开日期，同日返回时段不得早于离开时段；上午/下午选项同时受当前补助起止时段约束。修改补助日期或时段后保留已填的非补助内容，只标记越界、倒序或冲突的项，用户自行修正或使用原有删除操作；问题解决前阻止计算、预览与提交。锁定记录保持原快照和只读展示。持久化继续使用以下三种调整类型，单向调整各最多一条：

- 中途离开填写出发日期/时段及返回日期/时段；返回时段按返回出差地的出发时段填写。离开日上午给 0.5 天、下午给 1 天；返回出发日上午给 1 天、下午给 0.5 天；中间完整日期不补助，同日离开返回不额外扣除完整半天。
- 延后出发只填写实际出发日期/时段；此前不补助，实际出发日上午给 1 天、下午给 0.5 天。
- 提前结束只填写实际离开日期/时段，不要求返回日期；离开日上午给 0.5 天、下午给 1 天，之后直到审批结束不再补助。
- 审批原日期和类别保留。实际出发不得晚于提前结束；所有调整必须位于本项审批时段内，不能交叉、包含或重复占用同一个上午/下午，也不能重复扣除。重叠审批合并展示时跨原审批边界共同校验。同一天上午结束中途离开、下午再次离开允许；同一天实际出发和结束最多补助 1 天，净补助不为负。
- 未完成、越界、重复类型、倒序或重叠输入允许自动保存和恢复，但会提示并阻止计算、Excel 预览及提交。关闭补助保留输入，重新开启后恢复。已有边界调整可通过“恢复审批日期”移除并重新填写，保留中途离开；两端都越界或格式无效的旧草稿也可恢复，锁定内容不能重置。旧草稿中没有调整类型的时段视为“中途离开”；已锁定的版本 6–8 快照保留原金额、规范 JSON 和原说明，不使用新格式重写。

例如审批为 7 月 1 日上午至 10 日下午，2 日下午才出发，9 日上午提前离开，实际计补 7 天。页面、Excel 和 OA 共用后端计算结果。新报销的差补汇总为一项，Excel 和 OA 明细的发生日期取最后一个实际计补日（本例为 `2026/7/9`）；OA 说明为 `2026/7/2—2026/7/9，计补7天`。Excel 说明按实际计补时段逐段换行，如 `7/2下午—7/9上午，7天`，最后写 `7天 × 100元/天 = 700元`，不重复写“共几天”。跨年时每个时段端点都带年份。市内项目按年月列实际出勤日期，如 `2026年9月：1-5日、7日`，不写上午/下午，再写金额公式。说明在同一格内换行，超过 Excel 单行最大高度时才续行，金额和张数只写一次。OA 的审批起止日期仍保留关联审批的总跨度；历史锁定快照保留原日期、金额、说明和规范 JSON。

## Excel 输出契约

- 保留公司模板的标题、合并单元格、字体、边框、行列尺寸和 A4 打印设置。
- 姓名、部门从 Session 获取；前端不能覆盖。
- 页面只选择“预算代码”，服务器从对应 OA 选项取得完整标签填入 Excel 项目栏，保留正式模板表头；网页管理入口只维护实际需要的设置。
- Excel 和 OA 的普通费用明细按发生日期升序，同日按 Excel 下拉类别顺序，同日同类保持草稿保存顺序。差补汇总排在全部普通费用之后、合计之前。
- Excel 币种为“人民币”；国外票据的 `originalCurrency/originalAmount` 是原币参考信息，Excel 只写员工确认的人民币 `amount`。币种未知或存在外币警告时也必须确认，不自动猜汇率或将原币数值视为人民币。
- 原币参考金额上限为 `999999999999999.99`，人民币单项及报销总额上限仍为 `999999999999.99`；金额最多两位小数，按十进制处理，不用浮点数转换大额原币。
- 费用类别代码和中文名称只在后端公共契约中定义一次；模板现有 17 类全部可手工选择。自动识别覆盖已有样本支持的子集，不能识别的类别直接生成可编辑的“其他”费用行。
- 旅客运输发票优先按票面交通工具分类：铁路为“火车票”、航空为“飞机票”；已支持的公路/出租汽车类型及明确的“客运服务费”税目归为“市内交通费”。客运 PDF 同时从版面列恢复出发地和到达地作为可编辑说明；无法可靠判断时为“其他”并标记需要核对。
- 新出差补助汇总行的发生日期取最后实际计补日。说明按实际计补时段逐段换行，市内项目按年月列实际出勤日期，最后写天数、每日标准和金额的计算公式；按审批逐项舍入与合并计算存在分位差时保留逐项公式及金额相加，保持原总额。历史锁定快照沿用原日期和原说明。说明格自动换行、左上对齐并按内容调高行高；超过 Excel 单行最大高度时才续行，续行无类别、日期、金额、币种或票据张数，补助金额只计一次，主行票据张数为 0。
- 金额使用 `Decimal`；总额、人民币大写和票据张数由后端重新计算。
- 一份来源文件对应一张票据；费用带 `sourceFileId` 时，服务端将 `receiptCount` 规范为 `1`。没有 `sourceFileId` 的手工汇总行可关联票据照片/文件并调整张数；行程单/付款凭证不计票据张数，多张手工汇总不按合计金额强制要求付款凭证，单张仍按金额门槛判断。
- 姓名、部门、项目、日期文本、说明等所有来自用户、钉钉或 OCR 的 Excel 文本统一通过安全写入函数；首字符为 `=`、`+`、`-`、`@` 时按纯文本转义，禁止形成公式。
- Excel 回归测试必须分别向上述字段写入四种危险前缀，重新打开 `.xlsx` 后断言其仍为字符串、没有公式单元格，并检查 OOXML 中未生成外部输入公式。
- Excel 明细不受模板预留行数限制；超过第 54 行时按模板样式动态扩行，并同步下移总计行、扩展类别下拉和打印区域。部署默认保留 200 条费用明细的技术保护上限，可选补助由后端额外生成。预览内容写入内存后直接下载；正式提交内容从锁定快照重新生成并按 OA 附件生命周期处理。

模板坐标只在 `backend/app/excel/template_contract.py` 中维护：`C2` 姓名、`E2` 部门、
`G2:I2` 项目；第 4–54 行的 `B`、`C`、`D:F`、`G`、`H`、`I` 依次为类别、日期、说明、

## 实现原则

- 从免登、自动保存、票据/OCR、PDF/Excel 到 OA 提交使用同一份服务端权威数据；正式提交后只读不可变快照。
- OCR 获取文本，Parser 负责票据类型和字段；新增费用类别不要求新增 Parser。
- 内置 Parser 明确分类时不允许管理员关键词覆盖；仅当结果为“其他”时应用管理员关键词，同一票据命中多个不同类别仍保留“其他”并提示核对。
- 无法可靠分类、缺少字段或识别失败时，前端保留带警告的可编辑费用行；未完成字段仍可自动保存，汇总只计算完整行，Excel 预览和正式提交要求补齐。前端对每个文件分别发起请求，一张失败或超时不会影响下一张。
- 原始图片和 PDF 都由当前已鉴权页面读取为 Blob；预览弹窗立即打开，文件加载完成后，桌面端沿用浏览器内嵌 PDF 能力，移动端使用按需加载的 PDF.js 在当前页面 Canvas 中逐页绘制，不把受保护的 PDF URL 或 PDF iframe 交给钉钉 WebView。移动端缺少必要运行时能力或客户端加载、绘制失败时自动切换兼容预览，员工也可手动切换；兼容通道由服务器按需把当前页渲染为受限尺寸的 PNG，每次只生成当前页、复用有界文件校验进程槽，并对偶发的进程资源失败自动重试一次。
- 所有业务 API 必须鉴权，写接口必须校验 CSRF，管理员接口必须后端鉴权。
- CSRF token 只保存在前端内存；每次登录随新的 HttpOnly Session 生成新 token，同一登录 Session 内保持稳定，页面刷新或多标签页调用 `GET /api/me` 会取得同一个 token，避免标签页相互失效。
- Client Secret 只在后端；上传目录不可公开；原始 OCR 文本不入库、不写普通日志。
- 不提交含真实员工、项目或票据信息的样本；测试使用脱敏或合成 fixtures。

## 普通费用报销

- 在报销页顶部切换差旅报销和普通费用。各自恢复同一企业、报销人和经办人下的唯一当前草稿与材料，不按部门拆分，成功历史在同一入口按报销类型标明。新开、恢复和材料归属检查均在对应类型内处理。普通费用报销支持本人办理。没有当前单时，多部门用户先选择本次办理部门，单部门直接进入；有当前单时恢复其办理部门。基本信息的「更换部门」更正原单的办理部门，保留内容、材料和页面步骤，取消时继续原单。
- 普通费用表单按正式 OA 模板显示「报销主体」和「预算代码」，由员工独立选择。两种报销共用费用明细和材料编辑界面，普通费用由员工逐条选类别，选项来自正式模板的「费用科目」。已选科目停用时原费用行提示重选，其他费用仍可保存，重选后才能预览或提交。OA 的「明细说明」由各行费用的说明汇总，「费用科目」由各行类别去重得出，Excel 沿用相同格式并采用正式模板的科目选项。
- 管理员在同一个「OA 模板目录」中切换差旅与普通费用。两类模板均先读取检查，再确认保存。普通费用按正式字段自动核对，单独保存配置。
- 关联审批可留空，与差旅报销共用基本信息内的审批列表和起止日期、标题筛选。两种报销的查询结果均每页最多显示 10 张，翻页保留已选审批。普通费用的关联审批在报销主体和预算代码下方，默认收起。首次展开开关立即自动查询当前范围并连续获取后续结果，无需点击查询或手动续查；查询期间显示已找到的已通过审批数量，只有全部范围成功查完才显示完成。收起时保留已关联的审批和已查结果，暂停未完成查询，再展开自动继续；完成后再次展开复用本页结果。展开后只显示本人发起、已完成且结果为通过的不同模板审批，审批中、终止、拒绝或结果不明的记录不可新增关联。勾选或取消后自动保存；新增关联、可编辑 Excel 预览和正式提交前由后端重新核验归属和通过状态。默认查询近半年，可指定最近一年内的起止日期，移动端可展开筛选。桌面和移动端均提供常显的审批类别单选下拉，桌面与日期、关键词和查询按钮同行，移动端与筛选展开按钮同行，默认「全部审批单」，类别来自钉钉可见模板及已配置模板的真实名称，以模板代码筛选，不从实例标题推断。切换类别自动重新查询并保留日期、关键词和所有已选关联；已选但不在当前结果中的审批仍可查看和取消。分页凭据绑定类别，旧类别的延迟响应不能覆盖新结果。模板目录、审批列表或详情读取失败时明确显示查询未完成及失败环节，保留已成功查到的结果，不误称审批不存在；请求失败时重试接着失败位置查询，已被跳过的读取失败仍须重新查询当前范围。已选审批保存标题、编号、日期与状态，早期只有关联 ID 的草稿在展开列表时直接按已核验归属和通过状态的 ID 补读。旧稿中已保存的未通过关联保留展示并可取消，不静默删除，也不能据此继续预览或新提交。
- 普通费用在打开页面、返回前台、预览和提交时读取最新 OA 选项。报销主体或预算代码新增、显示名变化会自动同步，保留草稿中仍有效的选项值。已选值停用时仅要求重选受影响字段，其他费用和材料可继续保存，重选后方可预览或提交。
- 普通费用的关联查询和核验只读取所需的审批标识、标题、编号、发起人、时间、状态与通过结果，不受不同模板的无关表单控件和原部门字段影响。差旅字段带入与 OA 回读仍完整核验表单；其中仅略过字段名、值和附加值均为空且结构有效的说明控件（`TextNote`），实际业务控件的字段名、值类型和重复组件 ID 仍严格校验。审批摘要缺少必要信息或请求失败时，继续保留结果并如实提示查询未完成。
- 普通费用审批在标题旁显示状态，下方最多展示 3 条辅助说明，优先公司、项目、申请事项和日期。说明从同一次详情响应提取，去除空值、重复姓名、固定说明、附件、链接及复杂结构，选择项优先显示可读标签。长内容省略；桌面和移动端使用同一展示与搜索逻辑，标题、审批编号及已展示的说明均可搜索。新关联保存说明，刷新后继续展示；旧关联没有说明时沿用标题和编号。说明不可用不会影响审批选择、归属或通过状态核验，差旅保留已有行程、公司和预算信息。
- 科目选项值仍有效时，明细按最新选项打开和保存。Excel 生成期间选项或材料变化会重新核对，避免返回已失效的文件。可编辑普通费用报销预览成功后也会后台刷新下拉选项，保留其他草稿内容。锁定草稿时再次核对模板绑定、所选值及其对应的费用类别。提交队列在正式创建 OA 前再次核对普通费用模板与所选科目。如果办公费等科目的稳定选项值被改为住宿费，应重新核对该行并按新类别补齐证明材料。
- 尚有后续审批结果时，首批未命中仍自动继续查询，不提前显示当前范围无结果。查询期间暂时无法读取审批目录时保留进度。更改筛选条件时取消旧查询，点击查询后自动查完新范围；切换报销或离开页面不采用旧查询回包，移动端离开基本信息时暂停，返回后自动继续。已关联审批不可读取时仍可逐张取消。关联保存使用与 Excel 和提交核对相同的草稿模板绑定；明确限制可关联模板范围的普通费用 OA 模板需调整后才可确认。
- 普通费用与差旅的 Excel 预览采用相同的证明材料边界：费用计算字段完整且已有材料全部完成处理时，缺少必需的付款凭证、住宿明细或行程单仍可预览；复核与正式提交继续要求补齐。未关联证明文件、用途未确认、上传或识别未完成、来源票据去向未明确等材料问题仍阻止预览。
- 普通费用沿用差旅付款凭证及行程单规则。住宿费必须关联住宿明细。普通费用的快递费或差旅福利费中的快递可选关联运单明细，支持在费用行添加、更换、复用或移除关联。已上传未关联的运单也可随报销提交。附有发票号码的独立运单清单可将材料用途设为「运单明细」。
- 差旅福利费的快递和其他在票据分类关键词页分别维护。匹配快递词归为快递，两组同时命中时快递优先；未匹配快递词的福利费归为其他。普通费用按员工已选科目继续。快递条目在 Excel 和 OA 明细说明注明快递，并保留员工填写的完整说明。
- 桌面费用类型列和手机费用卡片只显示「福利费」，不追加「快递／其他」细分名称，与市内交通费的类型展示一致。编辑时仍可核对细分选择，快递的运单关联、分类及导出规则沿用已保存的细分。

## 报销输入与自动保存

- `GET /api/expense-categories` 返回后端集中维护的 17 类费用契约；`subsidy` 由系统生成，不可手工选择。新增类别只改集中契约，OCR Parser 映射保持独立。
- `POST /api/calculate/totals` 要求已认证 Session、有效的办理身份和 CSRF，不要求会话已选部门或存在当前有效部门。请求不接受姓名、部门、总额、人民币大写或自动类型的覆盖天数/标准。
- 八类每日标准由管理员分别配置，默认值见补助计算契约，0 元表示不发补助。类别取审批原值，日期只用于计算天数；各项可填写多个非补助时段。出差补助默认不申请，不再要求逐项勾选制度确认。
- 金额在 API 中使用两位十进制字符串，后端使用 `Decimal`，前端即时预览使用整数分；最终费用金额、补助、合计、票据数和人民币大写以后端响应为准。
- 可编辑报销申请补助时，最新计算未完成或失败，汇总与手机底栏显示待计算而非零补助，暂停 Excel 预览和提交，并提供失败重算入口。旧计算响应不覆盖新输入；保存复核或锁定前发现确认金额变化时，须核对最新金额再提交。请求重试保留原确认金额与幂等键，已存在的提交仍返回同一任务。锁定单据始终使用冻结金额和票据数，不受当前类别规则或日历影响，也不再重算。
- Pinia 是当前编辑状态，SQLite 是已保存内容的权威来源。普通输入约 600 毫秒防抖自动保存；关联审批选择立即进入串行核验和保存，并优先于尚未提交的普通输入。页面显示保存状态；审批核验期间保持派生字段和布局稳定、暂时禁用重复选择，失败时显示真实错误。刷新或换设备按企业、报销人、经办人及报销类型恢复唯一当前报销，提交先保存最新输入；员工无需创建、保存或管理草稿。服务端 API 保留 `draftId` 命名用于兼容和并发控制。
- 报销记录按当前钉钉登录人的企业及冻结的 OA 发起人查询，显示本人发起的差旅、普通费用和代办报销，最多 10 笔，按锁定时间从新到旧排列。记录显示原部门和报销类型，代办记录附报销人。旧快照未单独冻结发起人时沿用当时实际提交使用的报销人。浏览跨部门记录或按冻结快照重新生成 Excel 无需切换办理部门。处理中、重试、核验中、待人工核对和最终失败均在当前报销页处理，不进入历史列表，也不自动新开草稿。重新进入只恢复尚未退出工作区的当前记录。用户确认“新开一笔”后，旧内容退出工作区，原任务与审计证据保留；结果不确定的任务继续后台回查，不得重复创建同一笔 OA 审批。查看历史提交后可“返回当前报销”，按进入历史前的报销类型跨部门读取服务器实际当前单，历史记录的类型不改变原工作区及其首次部门确认状态；已有当前单时无需先选择 Session 部门。仍是原记录时恢复填写步骤，已在其他页面新开时打开新单，确认当前单为空时，首次办理部门尚未确认则返回该类型的选部门入口；已确认时准备空表。读取失败则保留历史页供重试。明确未创建 OA 的失败可“保留内容重新处理”，恢复完整材料后继续填写。
- 本人和代报各自保留当前草稿。代报草稿绑定企业、报销人和实际经办人，部门是可核验更正的办理信息。切换前保存原单未保存的输入，确认目标工作区后显示目标内容。上传或识别期间暂缓切换，已上传的原件、费用、识别结果和用途关系随原草稿保留，切回时一并恢复。切换不触发旧单清理。历史已锁定提交沿用已经冻结的 OA 发起身份和附件上传身份，创建结果不明时按原请求核对。
- 切换时可恢复已保存的工作区。OA 选项暂时不可用时显示原草稿、材料和提交状态，并提供重新加载选项。切换后加载尚未取得的费用类别。若代报保存因权限或办理对象失效被拒绝，经办人可确认舍弃本页未保存的修改并返回本人，服务器已保存的代报内容和票据随原单保留。
- 报销模板及全部已配置出差模板的发布时间、发布标识 `formUuid`，或公司、预算代码等选择项集合、显示名变化时，在流程标识和字段契约保持一致的前提下自动同步，不改变配置版本，不要求管理员重新读取保存。打开报销页、返回前台、查询审批、可编辑报销的 Excel 预览及正式提交时取得最新选项；返回前台的重复事件短时间内只刷新一次，审批结果同时带回同一目录的完整选项，较旧请求不能覆盖已采用的新选项，不替换本页输入或材料。当前草稿已选稳定值失效时只要求该草稿重新关联审批。映射控件的标题、业务别名或其他字段结构变化仍视为不兼容；已配置的出差类别被删除时说明具体原因并要求管理员重新确认，不自动猜选替代类别。重复保存契约和映射均未变化的目录保持配置版本及草稿绑定不变。尚未锁定且没有跟踪提交的内容遇到字段结构或映射变化，可在明确确认后“按新表单重新填写”。原记录保留，继续已有新版草稿或在空表中重新填写和上传材料。
- `POST /api/calculate/totals` 的每条计算费用保留 `id`、`source` 与完整费用字段；计算请求和 Excel 输入是不同契约，不能复用只保留 Excel 字段的裁剪函数。端到端请求模型测试覆盖此前的缺字段 422 问题。

返回前台的被动选项刷新不打断已有编辑：已有上次核验的选项且当前没有选项错误时，连接、网关、限流等读取失败保留原选项、未保存输入及材料选择，不显示为已刷新成功。明确的身份、权限、模板和配置错误仍提示并阻断；没有可用选项或员工显式重新加载时，读取失败仍正常提示。审批查询、Excel 预览和正式提交继续实际核验最新配置，不使用此回退绕过业务校验。

## Excel 生成与下载

- 报销页先自动保存当前内容，再调用 `POST /api/reimbursements/drafts/{draftId}/excel-preview`，要求 Session、办理归属、CSRF 和保存后的 revision，不要求 Session 部门与原单一致。保存等待期间重复点击只处理一次；切换账号、办理身份或报销后，原点击不再生成其他报销的预览。`trip=null` 表示不申请补助，不生成补助行。
- 桌面下载、原生下载凭证及原生下载在服务端统一拦截未完成恢复、已过期和已退出工作区的未锁定报销，生成 Excel 后再次核对状态。可编辑普通费用的 Excel 预览和提交核对使用同一模板绑定校验。已锁定的历史报销仍按原快照预览，下载凭证不能绕过后续状态变化。
- 报销输入只选择 `budgetCodeValue`；后端用绑定 OA Schema 的完整选项标签作为项目，不信任客户端另传项目覆盖。费用行保存原币、来源和行程单关联等辅助字段，生成 Excel 时只投影必要的公司模板字段；补助由后端生成。
- 报销页导出的姓名取服务器核验的报销人，部门取原单已保存属性；锁定历史使用冻结快照。可编辑报销的补助设置、有效天数、补助金额、费用合计、总额、票据数和人民币大写均在生成时重新计算，锁定历史不按当前设置重算。
- 后端只读加载 `backend/app/templates/expense_template.xlsx`，先做 ZIP 安全预检（10 MiB 文件、200 条目、20 MiB 单条目、50 MiB 总解压体积、200 压缩比上限，并拒绝重复或越界路径），再验证唯一可见 `费用报销模板`、标签、合并区域和精确的 17 类 `B4:B54` 字面列表验证。生成内容超过模板预留行时，服务按第 54 行样式扩展明细、类别下拉和合并区域，将总计行及打印区域同步下移；保持样例的 A4 纵向、页边距和打印设置。公式或自定义数据验证、普通公式、超链接、额外定义名、打印标题、条件格式、表格/计算列、透视、图表、图片/绘图、切片器、批注/注释、外部关系或链接、宏/VBA、数据连接、QueryTable、ExternalLink 和嵌入活动内容一律拒绝。写入 `BytesIO` 后再次验证并直接流式返回，不创建临时 Excel。
- 所有外部文本都会清理控制字符并限制长度；去除前导空白后以 `=`、`+`、`-`、`@` 开头的内容加文本转义前缀，确保不会形成公式。
- 正式提交附件为 `票据汇总-姓名-YYMMDD-序号.pdf` 和 `差旅费报销单-姓名-YYMMDD-序号.xlsx`（纯补助无材料时只有 Excel）。姓名使用服务端核验的报销人；日期为提交锁定当天的上海日期，序号按同一企业、同一报销人当天的所有报销提交统一递增，差旅、普通费用和不同经办人／部门合计计数。失败任务不回收已发编号，同一任务的重试、回查及锁定 Excel 下载均沿用冻结编号；已有历史和在途快照保持原名。未提交预览不占号，仍使用 `差旅费报销单-姓名-预算代码标签.xlsx`。项目文件名片段独立限长，替换 `/\\:*?"<>|` 和控制字符，并通过 RFC 5987 的 `Content-Disposition` 返回。前端以 Blob 下载并及时释放对象 URL；Excel 项目正文保留完整标签并按需扩展标题行。

替换模板时必须先在副本中彻底脱敏，确保只有一个可见 `费用报销模板`，不含公式、超链接、额外定义名、
打印标题、条件格式、表格/计算列、透视、图表、图片/绘图、切片器、批注/注释、外部关系或链接、
宏/VBA、数据连接、QueryTable、ExternalLink 或嵌入活动内容，并通过上述 ZIP 预检和严格部件白名单；
同时保持基础模板的上述坐标、`D4:F54`/`C55:F55` 合并及精确的 17 类 `B4:B54` 字面列表验证。运行时只允许生成服务按受控规则扩展这些区域，并继续保持样例的 A4 纵向、页边距和打印设置。随后运行完整 Excel 回归测试。不得修改桌面业务样例原件，也不要通过放宽模板契约来掩盖模板版本差异。

## 材料、OCR 与资源限制

当前报销页使用报销记录级文件接口，依靠服务端持久内容完成预览、恢复和正式提交：

- `POST /api/reimbursements/drafts/{draftId}/files` 按 `expectedRevision` 上传一份 `EXPENSE_SOURCE` 或 `ATTACHMENT_ONLY`；证明材料另传查询参数 `attachmentKind=itinerary|payment_proof|hotel_bill|waybill|other`（默认 `other`），响应持久返回该用途，PATCH 可修改用途。费用来源只能为 `other`。元数据和 OCR 状态写入 SQLite，文件字节写入受控 staging。票据 PDF 单页，证明材料 PDF 最多 30 页；页面刷新、进程重启或换设备后通过身份和归属检查恢复。
- `GET /api/reimbursements/drafts/{draftId}/files/{fileId}/content` 返回原件用于图片及 PDF 的鉴权 Blob 预览，校验企业、报销人、经办人、文件状态、有效期、大小和 SHA-256，响应禁止缓存；关闭或切换预览时释放 Blob URL。
- `GET /api/reimbursements/drafts/{draftId}/files/{fileId}/preview/pages/{pageNumber}` 是 PDF 兼容预览通道，对已经过相同归属与完整性校验的 PDF 按需渲染一页 PNG，最多 30 页、单页最多 250 万像素和 2200 像素边长；双端只保留当前页的 Blob URL 并提供翻页，偶发的渲染进程资源失败自动重试一次。
- `POST /api/reimbursements/drafts/{draftId}/files/{fileId}/ocr` 持久结构化 OCR 候选和状态。费用行通过 `sourceFileId` 关联票据；每份终态票据正式提交前必须计入费用或被员工明确选择仅作为材料保留。自动保存允许尚未完成这项选择；后端完整性检查会拦截未处理票据。
- 行程单通过费用行 `itineraryFileIds` 关联同一报销中的活动 `ATTACHMENT_ONLY + itinerary`，付款凭证通过 `paymentProofFileIds` 关联活动 `ATTACHMENT_ONLY + payment_proof`；普通材料不能冒充任一种证明。网约车必须关联至少一份行程单，允许多笔费用分别选择同一份多行程 PDF。删除、改角色或改用途会原子清理旧引用并重新要求补齐。来源票据改为明细或证明材料时，前端同步移除对应费用行和该文件的忽略标记，保留原文件及其他费用的有效关联，后续自动保存不再携带旧来源引用。确认原用途不重新识别或恢复已忽略的费用；重新识别和采用识别结果使用各自的明确入口。删除失败后回读为“删除中”时，同步解除该文件的费用引用和忽略标记，保留清理错误及“重试删除”，不显示为已完成；回读仍为活动文件时保留原费用。
- 桌面和手机的「付款凭证」栏右侧保留「关联付款凭证」，已附凭证后仍可在同一弹窗补充上传、选择或移除选择，确认后更新引用；上传失败、取消均保留原关联。只读时禁用，已提交明细不显示编辑入口。确认时重新检查费用关联及所选文件的当前状态和用途，有变化时提示重新核对，避免覆盖其他修改。
- 每笔住宿费必须通过 `hotelBillFileIds` 关联至少一份活动的住宿明细文件；姓名、入住/离店日期、价格等字段只做尽力识别，字段缺失不单独提示，也不阻止提交。
- 行程单、住宿明细和付款凭证允许先上传、保存，未关联费用时归入“待关联材料”，可直接选择对应费用；没有合适费用时明确提示先添加或编辑费用，也可修改用途或删除。未关联的证明材料阻止 Excel 预览和新 OA 提交，不自动混入普通附件；“其他材料”可独立随单提交。解除关联后重新检查，已锁定提交继续使用原冻结材料清单。
- 行程单识别结果保存在文件的 `ocrResult`，以 `kind=itinerary` 与票据候选区分，包含汇总和逐段行程，不新增费用或金额。前端只对完整、无警告且唯一的候选自动关联：先看明确的同类发票号/订单号，再看人民币金额、发生日期及有方向的起终点；号码矛盾、路线反向、候选重复或部分识别时交人工。已有手工关联不被覆盖，文件名不作为匹配证据。
- 员工手工改变或清空行程单关联时，费用输入保存 `itineraryAutoMatchDisabled=true`，刷新后仍尊重人工选择；只有显式重新自动匹配才恢复为 `false`。该严格布尔值默认 `false`，只记录编辑意图，不进入金额计算或不可变提交快照。
- 行程单 PDF 仍允许上传/打印全部最多 30 页；识别先检查全部页面，再逐页优先读取原生文字，扫描/混合页最多回退本地 OCR 5 页。整份文件共用现有 OCR 超时（默认 120 秒）和单进程准入槽，同文档复用模型。超限、缺关键字段、币种/金额/日期冲突或未解析续页时 `complete=false` 并带警告，仅供人工参考；识别是否完整不改变最终打印的原 PDF 页面，不把外币金额当作人民币匹配。
- 付款要求由后端按员工确认的人民币票面 `amount > 500.00` 独立计算，不信任客户端必需标记，不使用原币数额、不除以 `receiptCount`，本期不引入分摊/部分报销金额或票据验真。铁路 `railType` 为 `high_speed/emu/regular/unknown`；仅 `category=rail_fare` 且 `high_speed` 暂时豁免。已识别高铁允许员工改成动车或普通列车并按非豁免处理；已识别动车或普通列车不能改成高铁取得豁免，未知类型和未分类/失败的 `other` 允许员工补选；已知非铁路证据不能伪标铁路取得豁免。复核和正式提交均严格校验。
- 新增出租车和国外票据本地解析器；国外票据保存 `originalCurrency/originalAmount`，并用 `originalDetailsEdited` 记录员工是否已经修正或清空原币字段，防止恢复或再次核验时被旧识别值覆盖。兼容该标记引入前保存的草稿：已保存原币值与当前识别证据不一致时按人工修正保留。人民币 `amount` 留给员工填写并确认 `cnyAmountConfirmed`。来源为 `foreign_receipt`、含外币警告或 `requiresCnyConfirmation` 时，即使币种未知也必须确认。
- 当前未提交报销的文件保留到 `expiresAt`；确认新开后，普通旧草稿的空闲文件按废弃规则提前清理。成功提交须全部冻结附件从 OA 回读并均为 `LINKED` 后才清理本地副本。明确安全的失败原件保留到原 `expiresAt`，到期独立释放；正在复制恢复材料时暂缓来源清理，不确定结果始终保留。详见 [文件生命周期](DINGTALK_OA_INTEGRATION_DESIGN.md#13-文件保留和清理规则)。

### 提交材料汇总

服务器按与 Excel 和 OA 一致的费用顺序生成票据汇总 PDF，正式文件名按上述编号规则生成。每笔费用的材料依次为来源票据、手工票据材料、对应住宿明细、对应行程单、对应付款凭证。共享材料只在排序后第一笔引用它的费用中放入一次，允许独立提交的其他材料按上传顺序追加。同一笔报销再次选择字节完全相同的文件时直接提示并跳过，不重复上传或识别。原 PDF 逐页保留文字、图像、尺寸和旋转；照片按 EXIF 方向纠正、等比放入 A4、透明背景转白，保持完整图片边界。合并结果直接使用原件内容，用于阅读打印，不以 OCR 文本重建票面，也不承诺保留原 PDF 数字签名效力。

新提交在版本 13 快照中冻结编号、实际明细行序和 PDF 材料顺序。调整类别排序权重后，已锁定单据继续使用快照中的顺序和 OA 字段值。重新生成 Excel 须使用快照绑定的模板或已登记的兼容模板。历史快照保留原规范 JSON 和 SHA-256。

差旅和普通费用新提交统一使用 `snapshotVersion=13`，额外冻结 `documentNaming.submissionDate/sequence` 及正式附件名；版本 11 差旅、版本 12 普通费用和更早快照保持原内容及名称。差旅冻结市内出勤日期；新市内提交额外冻结 `attendanceDescriptionFormat=monthly_ranges_hyphen`，OA 和 Excel 共用短横线日期区间（如 `1-5日`）；已冻结 `monthly_ranges` 的单据继续使用原长横线说明及原规范 JSON/SHA-256。未带 `attendanceDescriptionFormat` 的历史版本 11 始终保留原逐日说明、规范 JSON 和 SHA-256，锁定预览、后台续跑、严格 OA 回读与已提交恢复均按冻结格式执行，不依赖当前日历；版本 10 的附件模式继续适用，额外冻结 `attachmentMode`（`excel_only` 或 `bundle_and_excel`），冻结三种补助调整的类型、实际日期时段、详细 OA 说明、手工费用票据材料关联、扣除天数和完整补助类别；已锁定的版本 6–10 快照保留原金额、规范 JSON 和原 OA/Excel 说明，继续支持回读及恢复。版本 6–9 保留两附件规则，版本 10 保留其冻结的附件模式。快照还冻结附件用途、证明材料关联、铁路类型、逐张出差审批对应的补助项、发起部门、来源类别和日期区间；有材料时上传顺序 0 的 `GENERATED_PDF` 和顺序 1 的 `GENERATED_EXCEL`；纯补助且无材料时仅上传顺序 0 的 `GENERATED_EXCEL`。OA 附件数量和顺序必须与冻结模式完全一致。汇总最多 500 页并受单对象容量限制；生成或上传失败使用持久检查点恢复，原件只有本地来源记录。

数据库迁移头为 `20261125_0030`。0030 只更新附件清单触发器以支持版本 13，保留原表、数据和严格数量／顺序约束；存在编号快照时拒绝降级，跨版本降级先检查已有数据保护再修改 DDL。0029 增加报销类型、运单明细和福利费子类，保留现有差旅草稿和提交快照。存在新类型、运单、新快照或不可保留的福利费设置时拒绝降级。0028 单独保存兼容变更前的草稿模板绑定版本，保留原草稿、审批关联、票据及提交快照。存在需要保留的旧绑定时拒绝降级。0027 为草稿和提交增加不可变的经办人字段，历史本人记录保留原值和快照，存在代报授权、代报记录或有效的部门管理员授权时拒绝降级。0026 允许已确认无 OA 的附件清理安全转入重试或人工核对，仍禁止再绑定 OA 或重新创建；恢复审计按提交与原状态版本唯一，保留每次独立核对依据。重复恢复审计或暂停中的清理存在时拒绝降回旧约束。0025 增加当前报销的放弃标记及失败恢复的唯一来源和进度；有放弃或恢复记录时拒绝丢失语义的降级。0024 为版本 11 出勤日期快照保留附件清单保护，不改写已有记录；存在版本 11 快照时拒绝降级，跨版本降级同时提前检查旧版本 10 保护。0023 按功能移除要求删除辅助 `runtime_events` 表及其历史运行记录，业务记录、提交快照和恢复审计保持不变；降回 0022 只重建空表，历史运行记录只能从升级前备份恢复。0021 的附件清单规则保持不变：纯补助单允许一份已关联 Excel，普通报销和旧快照仍要求 PDF＋Excel；存在版本 10 提交时拒绝降回旧附件规则。部署前应一致性备份 SQLite 与 staging，再通过原启动命令执行迁移并重启加载新代码。

0029 的表结构、数据整理、触发器和迁移版本在显式 SQLite 写事务内一同提交，执行失败时整体回滚。旧版本迁移中断后已留下的报销类型或福利细分列，只有类型、空值、默认值及必要约束与该迁移一致时才允许续跑；已有细分值不覆盖。不能通过强改迁移版本号或跳过约束来恢复。

### 文件解析和资源防护

- 持久材料上传使用 multipart 字段 `files[]`，要求已认证 Session、办理身份与草稿归属、可编辑状态、revision 和 CSRF 校验；不要求当前 Session 已选部门。每个请求只携带一个文件；后端先取得全局准入和 Session 上传租约，再流式解析正文。单文件最多 20 MiB，请求体上限 25 MiB（含 multipart 余量）；`Content-Length` 只用于提前拒绝，流式计数才是权威限制。单笔报销默认最多保留 200 个文件、合计 100 MiB。
- Nginx 的 `client_max_body_size` 设为 25 MiB，为一个 20 MiB 文件的 multipart 边界和请求头预留余量。
- 文件扩展名、magic bytes 和实际解析结果必须一致。Pillow 图片解码、PDF 预检/文本提取和 OCR 在可终止的标准库 `spawn` 工作进程中执行。文件验证使用独立单槽并只短暂等待；OCR 仍固定为一个执行槽，并使用进程内有界 FIFO 等待队列（默认最多 8 个等待请求、等待 150 秒），不同用户按 OCR 请求到达顺序公平准入，不增加并行模型数量。队列满或超时返回可重试的 `OCR_BUSY`，单次执行超时或资源终止返回 `OCR_TIMEOUT` / `OCR_FAILED`；等待和执行总时限同时用于判断持久 `RUNNING` 状态是否真的中断。取消请求时，准入令牌会一直保留到该子进程终止并回收，然后同步关闭 spool 并删除 `.part`/最终文件。PDF 资源检查递归覆盖 Form XObject 及图片遮罩，并分别限制页面内容流数量（默认 512）和 XObject 总数（默认 100），同时限制嵌套深度、MediaBox/渲染像素、全部内嵌图片累计像素和每页解压后内容流字节数。
- 上传缓存路径只使用服务端 Session 哈希与随机 UUID；取消和退出会清理未落入报销 staging 的缓存。实现不跟随符号链接，不写 OCR 原文或 sidecar。
- 持久 OCR 接口每次处理一个报销文件，保存来源关系和状态；金额使用两位十进制字符串。
- 单页数字 PDF 先使用原生文本；文本过短、解析后仍缺金额或日期、火车票缺路线，或者旅客运输票据仍无法分类时，才执行一次本地 OCR 回退。客运 PDF 的起终点优先使用 pypdf 版面列提取；纯图片 OCR 若把出发地与到达地合成一个跨列文字框，则根据已识别的表头坐标分别裁切两个单元格并二次识别，不凭扁平文本猜测列边界。不记录姓名或证件号。常规自动测试使用显式 fake engine；默认本地开发、OCR 冒烟测试和生产使用真实本地推理，生产禁止 fake。
- 普通发票金额依次优先使用票面数字“价税合计”、大写“价税合计”、或明确的“合计 + 税额”；单独的未税“合计”不会被当成最终报销额。旧版增值税发票二维码只作为补充证据。二维码金额与票面总额一致，或“二维码金额 + 税额 = 票面价税合计”时可提高可靠性；冲突时保留票面总额并提示人工核对；票面缺少金额而只从二维码取得候选时也必须提示核对。二维码中的开票日期不覆盖火车票乘车日期或旅客运输发生日期。动态二维码和未知格式会被安全忽略，不上传、不访问二维码链接、不记录原始载荷。
- 管理员在“系统设置 → 票据分类关键词”按费用类别分组维护全部分类词；该区域显示在每日补助设置之前。设置页与报销页共用 `GET /api/expense-categories` 返回的后端类别契约：系统生成的“出差补助”不显示，“其他”显示为自动兜底且不能添加关键词。关键词至少 2 个字符，均可新增、修改、移动类别或删除，最多 500 条。市内交通费再分通用、网约车、出租车三组，运营商名称（包括滴滴出行、滴滴畅行）统一在这里维护；网约车词会要求关联行程单，通用和出租车不强制要求。后续识别采用数据库中的当前配置，没有另一份隐藏运营商兜底名单，删除不会在启动时补回。不同费用类别同时命中时保留为“其他”。旅客运输发票在交通工具字段、明确运输服务税目或带运输服务证据的交通类型词中匹配；被数字列打断的税目只拼接能补全配置词的续行，不用目的地酒店名称推断机票。日期、金额、表头和火车票等专用版式的结构判断保留在解析器中。`GET/POST/PUT/DELETE /api/admin/receipt-keywords` 均由后端管理员权限保护，写操作同时校验 CSRF，只有市内交通费允许设置交通类型。
- 本地 OCR 依赖精确锁定为 PaddleOCR 3.7.0、ONNX Runtime 1.23.2、OpenCV 4.10.0.84 和 pypdfium2 5.13.0；后两项用于本地二维码识别和单页 PDF 渲染。开发安装和正式镜像均默认包含 OCR。Linux/amd64 是正式部署路径并要求 AVX CPU；macOS/arm64 仅作为本机 CPU 开发测试路径。默认使用 `onnxruntime` 的 CPU 后端，`OCR_CPU_THREADS` 控制每个模型的算子线程数。模型二进制不入库；正式镜像构建时按固定清单从官方源下载并校验两套 PP-OCRv6 small ONNX 制品，内置为只读文件并附带来源/许可证说明。本地开发仍可使用经过同样校验的宿主模型挂载。运行时不会下载模型或回退云服务。
- `OCR_MEMORY_PROFILE` 默认 `standard`，保留标准推理配置；小内存测试机可显式设为 `low`，关闭 ONNX Runtime CPU 内存 arena 和 memory pattern 缓存，文字识别逐个裁片执行，并将文字检测的内部工作图长边限制为 1280 像素。两种模式使用相同的固定模型、原始文件和字段解析规则，不改变文件安全检查、OCR 单槽队列、超时及空闲回收策略。低内存模式可能影响密集小字的检出，必须用目标业务样本核对准确率，不能把合成样本通过当作所有材料的资源或准确率保证。
- 模型目录和运行依赖缺失或不匹配时 readiness 失败。镜像检查在断网环境分别用两种内存模式的真实 OCR 服务核对合成出租车票据和扫描行程单的金额、日期与路线，并在 700 MiB 硬限额容器中交替识别大小合成图片，检查原生内存回归；部署性能以原生 Linux/amd64 目标机实测为准。

尚未上传成功的本地文件保留在材料处理列表，继续上传不会覆盖原失败项或丢失重试来源；重试只发送该文件，明确移除才放弃该失败项。清空已上传材料不清除本地失败文件。仍有本地失败项时，桌面和手机均阻止 Excel 预览、复核和新 OA 提交，并提供定位处理入口；切类型、查看历史和进入设置同样要求先处理，刷新或关闭页面会提示确认。明确确认新开仍可放弃当前报销内容。

前端只提供一个“费用明细”区域；每笔费用集中显示票据、对应行程单/付款凭证、警告及一组操作，上传/识别中和未分配材料也显示在同一区域。批量选择后先为全部文件建立稳定占位，再逐份上传和逐份识别，显示整批进度；完成后统一加入费用。服务端返回 `FAILED`（包括自动分类失败且没有普通 `ocrResult`）时，批次明确显示“需要处理”而不是误报完成；单份上传失败可就地重试或移除，重试不会重放已成功文件；已上传但识别失败、中断或没有可用结果的材料可单独重新识别、确认用途或删除，已有可用识别结果时通过编辑修正而不再常驻显示重复识别入口。切换报销人、报销类型、当前单或退出登录时不采用旧响应；同一单据更正部门保留本地失败文件及其重试目标。前端从后端公开配置读取技术保护上限，默认可处理 200 条费用明细。员工可预览来源、编辑金额、处理异常识别、删除或仅保留材料；文件关系由持久 ID 维护，不再重复渲染完整附件卡片和完整费用表。页面展示结构化结果，原始 OCR 文本不入库。

新增解析规则复用现有本地模型，优先原生 PDF 文本，只在必要时执行 OCR；出租车/境外专门字段规则在本地轻量执行。实际耗时还包括图片大小、上传和每次工作进程初始化，应使用目标服务器实测值评估，不能用少数样本宣称全部国外票据的准确率或固定秒数。

上传流先进入 `<TEMP_DIR>/.spool`，单文件只允许 256 KiB 留在内存，超过后转为可计量的磁盘缓存；校验后立即转存到报销 staging 并关闭、删除缓存。全局缓存默认限制为 768 MiB，包含活动/残留 spool 和 `.part`；清理会跳过仍在使用的缓存。上传、识别和删除在 Session 租约内重新确认身份、公司和有效期。生产容器以固定非 root 用户运行，后端不直接发布端口，只由 Nginx 反向代理访问。持久报销文件由 revision、`expiresAt` 和提交状态机控制。

工作进程在 Linux 上保留宿主硬限额，只调整可恢复的软限额：文件/PDF 验证默认 512 MiB，OCR 默认 5 GiB 虚拟地址空间（推理和图像处理依赖会预留虚拟映射，虚拟地址限额不等于实际常驻内存），每页 PDF 解压后内容流默认最多 32 MiB，同时限制生成文件大小、打开文件数、CPU 时间并禁止 core dump。源码 Compose 默认使用 3 GiB 容器实际内存和 128 PID 上限；发布部署的 16C/32 GiB 资源配置见[服务器部署](deployment/README.md)。正式 OCR 必须运行在支持这些限额的 Linux x86_64/amd64 环境，不提供绕过生产限额的开关。

PNG/JPG 安全检查使用独立的轻量入口，子进程只加载图片校验所需依赖，不导入 Web、PDF 或 OCR 模型模块；每次检查仍使用全新隔离进程，沿用原有类型、完整性、像素、符号链接与资源限额检查以及超时回收。OCR 保持现有单进程短时复用策略，不因图片检查轻量化改变并发、预热或空闲回收规则。
